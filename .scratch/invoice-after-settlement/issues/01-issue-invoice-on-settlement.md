# 01: صدور و خواندن فاکتور بعد از تسویه

**What to build:** بعد از تسویهٔ موفق زرین‌پال، دکتر همان سفارش و ادمین یک فاکتور فریزشده را با چیدمان نمونه می‌خوانند. پرداخت ناموفق و مرحلهٔ قبل از تسویه سند ندارد. بازگشت تکراری درگاه همان سند را برمی‌گرداند.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] تسویهٔ موفق دقیقاً یک فاکتور برای همان سفارش می‌سازد و دکتر مالک و ادمین آن را دانلود می‌کنند.
- [x] دکتر سفارش دیگر آن را نمی‌بیند.
- [x] پرداخت ناموفق و سفارشِ هنوز تسویه‌نشده فاکتور ندارند.
- [x] callback تکراری فاکتور دوم نمی‌سازد.
- [x] جمع نهایی ریال برابر مبلغ تومان پرداخت ضربدر ۱۰ است. ستون تخفیف صفر است، حتی اگر روی سفارش تخفیف ذخیره شده باشد. عوارض صفر است و مالیات با درصد لحظهٔ تسویه فریز می‌شود.
- [x] تغییر بعدی درصد مالیات یا قیمت دسته و متریال، سند ذخیره‌شده را عوض نمی‌کند.
- [x] هر دندان یک سطر با عدد ۱ است؛ شرح شامل عنوان دسته، شماره دندان و نام بیمار است. اگر سفارش VIP باشد یک سطر خدمات ویژه دارد. اگر جمع سطرها با مبلغ پرداخت نخواند، یک سطر «خدمات لابراتوار» با همان جمع پرداخت‌شده ساخته می‌شود.
- [x] کد کالا، شماره مالیاتی، شماره اقتصادی خریدار، شناسه ملی خریدار و شهر خریدار خالی‌اند. بلوک فروشنده خالی است. فروش نقدی است. کد پیگیری در توضیحات است. خروجی سه برچسب نسخه دارد و جای مهر و امضا خالی است.

## Comments

صدور داخل همان تراکنشِ گذار پرداخت به `paid` است. دکتر مالک و ادمین سند را از `GET /api/order/:id/invoice` می‌خوانند و فایل را از `GET /api/order/:id/invoice/download` می‌گیرند. بازگشت تکراری درگاه همان سند را برمی‌گرداند و سند دوم نمی‌سازد. پروفایل فروشنده در issue بعدی است؛ تا آن موقع بلوک فروشنده خالی می‌ماند.
